# C# WPF 与 HTML/WebView2 客户端资源对比

当前复测请看 [2026-11-11 性能报告](RESOURCE_COMPARISON_2026-11-11.md)。本页为历史记录；旧宿主后来发现未解除正式 Startup 事件，可能影响单实例或窗口数量，因此不用于计算新版本优化比例。

2026-11-09 本机测试。当前“C 版”实际为 C# WPF，后端仍复用 Python。本页数据是刷新优化前的历史基线。

## 结论

本次固定数据、前台服务监控场景中，C# WPF 的专用内存提交量低约 **49.0%**，进程数从 7 个降至 1 个；HTML/WebView2 的空闲 CPU 更低。不能把这个结果写成“C# 所有资源都更低”。

| 客户端 | 专用内存 Private Bytes | 工作集总和 | 整机空闲 CPU | 客户端进程数 |
| --- | ---: | ---: | ---: | ---: |
| C# WPF | 188.1 MiB | 208.0 MiB | 0.795% | 1 |
| Python + HTML/WebView2 | 368.9 MiB | 492.9 MiB | 0.046% | 7 |

每项取三轮结果的中位数。工作集可能重复计算跨进程共享页，因此以 Private Bytes 为主要比较项；Private Bytes 是专用提交量，不等于当前实际驻留的物理内存。CPU 按本机 24 个逻辑处理器归一化；单核口径分别为 19.071% 与 1.108%。

## 测试口径

- Windows 11 25H2，build 26200；16 个物理核心、24 个逻辑处理器，约 31.7 GiB 内存。没有记录主机名、用户名或硬件序列号。
- C# 为 Release 构建、.NET 10 WPF，使用生产 `MainWindow`、资源与真实 API 轮询方法。测量 DLL SHA-256：`432300fa472c237e06e1064fd4f26281095ee4ad5ace8656e1862931b472d603`。
- HTML 使用仓库现有 `static/`、`ops` 主题、Python 3.12.8、pywebview 6.2.1 与系统 WebView2；宿主导入原 `desktop` 模块，使用相同的窗口创建参数和 Edge Chromium 渲染方式。
- 两版窗口均设为 1440x900，显示服务监控；HTML 标准窗口边框使内容区为 1424x861，WPF 自绘标题栏包含在 1440x900 中。两版没有最小化或隐藏。
- 同一个仅绑定回环地址的只读夹具提供完全相同的 JSON：6 个虚构项目、4 个监听服务、3 个关注进程。固定项目图标避免网页自动抓取 favicon；不探测这些虚构端口。
- 使用真实两秒轮询。每次全新启动，准备完成后预热 15 秒，再以一秒间隔采样 30 秒。顺序为 WPF、HTML、HTML、WPF、WPF、HTML。
- HTML 计入 Python 宿主和全部 6 个 WebView2 后代进程，包括浏览器、GPU、网络与渲染器；WPF 计入完整客户端进程。采样器和夹具服务不计入两版。
- 每轮预热及采样期间读取状态 22 至 23 次。HTML 就绪检查确认数据已渲染、页面未隐藏、无脚本错误；六轮夹具合计 142 次状态请求、0 次写请求、0 个 404。
- 关闭的仅是测试刚创建的进程树；现有安装版、真实项目、受控锚点和开机自启配置均未修改。

## 适用范围

这是客户端渲染层的比较，没有运行两套生产后台，也不是两个正式安装包的整机总占用测试。WPF 通过隔离宿主跳过真实后台启动；两版均未创建托盘菜单或开机启动项。生产模式还需计入 Python 后台的扫描、缓存、日志及进程管理开销，本表的节省比例不能直接用于整套软件。

未测试显存、安装体积、托盘待机、大量服务刷新、长日志滚动、长时间内存增长或其他电脑。CPU 差异的具体贡献尚未逐项剖析；当前 WPF 仍每两秒重建列表，后续优化应保留选择、焦点及操作安全校验。

当前 C# 仍为预览版，本次没有覆盖旧安装版或发布 Release。

## 2026-11-11 后续优化

源码改为前台每 5 秒刷新、隐藏/最小化暂停轮询、只重建可见页面，并通过轻量健康接口获取后台 PID，避免后台身份探测反复触发完整服务扫描。已完成新的三轮客户端比较，结果及测试限制见 [2026-11-11 性能报告](RESOURCE_COMPARISON_2026-11-11.md)，不覆盖上述历史数据。
